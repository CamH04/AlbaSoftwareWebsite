## Introduction

Software guidelines are an often skimmed over aspect of large scale projects as it can be seen as one of the duller parts of large scale and safety critical software , but as Ben Hosking bluntly put it:
"Boring is Beautiful in Software Development" (Hosking B 2022). As you could imply such standards are a key aspect of safety critical software of which NASA definitely falls under. They have
a strict set of 10 rules they abide by in all software. These guidelines , unlike many others, are rather short but this is a pillar of their philosophy when it came to creating the rules. Having a small amount of clear rules makes code-bases "more thoroughly analyzable, for properties that go beyond compliance" (Holzmann, G. n.d.). All code at NASA is written in C justified by its long history and large tool support such as source code analyzers, testing tools and debuggers therefore giving the development team to optimize and check the reliability of the code more thoroughly.

## Rule 1:

"Restrict all code to very simple control flow constructs - do not use goto statements, setjmp or longjmp constructs, and direct or indirect recursion".

This rule refers to keeping the logic and the steps the program does simple, to do the task in the simplest way possible.

A Goto statement in C is a keyword that jumps unconditionally to the labeled statement, this creates logic that is extremely hard to follow in some cases. An example of this in use would be:

```
Foo:
  Statement 1;
  Statement 2;

Bar:
  Statement 1;
  goto Foo; <-----
  Statement 3;
```

In this example it is easy to understand that "Statement 3;" inside Bar will never be reached but in complex programs or used in abundance can create many complex control flow structures, making it immensely complex to debug.

setjmp() acts as a non local goto, saving the current stack environment which can then be resorted by longjmp(). This, like goto, creates chains of potentially complex logic by saving and restoring states of the stack. An example would be:
```
jmp_buf buf;
void func(){
  printf(\"Print 1\\n\");
  longjmp(buf, 1);
  printf(\"Print 2\\n\");
}

int main(){
  if (setjmp(buf))
    printf(\"Print 3\\n\");
  else {
    printf(\"Print 4\\n\");
func();
}
return 0;
}

// Output:
// Print 4
// Print 1
// Print 3
```

Recursion (calling a function cyclically) is all together barred by rule 1. The two types of recursion refer to how the cycle of function calls is done either by calling he function within its own scope directly (direct) or by function A calling function B which then calls function A (indirect). It is not allowed as it goes against the title of the rule (like the other functions / keyword before), it creates complex chains of logic that become increasingly harder to follow with each subsequent level of recursion. As well as this it can create , as the NASA document states later on, "runaway code". Examples for direct and indirect recursion:

```
void Direct(int num){
  Direct(1);
  print("%d", num);
} // this will infinitely print 1

void Indirect1(){
  Indirect2();
}
void Indirect2(){
  Indirect1();
}
```

## Rule 2:

"Rule: All loops must have a fixed upper-bound. It must be trivially possible for a checking tool to prove statically that a preset upper-bound on the number of iterations of a loop cannot be exceeded. If the loop-bound cannot be proven statically, the rule is considered violated"
